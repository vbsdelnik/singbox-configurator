# singbox-configurator

Конвертирует VLESS-ссылки и подписки 3x-ui в конфигурацию sing-box. Формирует список узлов, группу автоматической проверки URLTest и ручные селекторы. DNS, TUN и правила маршрутизации задаются шаблоном.

Для генерации нужен Python 3.9 или новее. Сторонних Python-библиотек нет. Для опциональной проверки нужен установленный sing-box. Схема штатного шаблона проверена с sing-box 1.14.4.

## Откуда взять ссылки

В панели 3x-ui откройте нужный inbound и найдите клиента. В данных клиента скопируйте ссылку, начинающуюся с `vless://`. Для массовой сборки сохраните каждую ссылку в отдельный текстовый файл в [`vless-links/`](vless-links/). Имя файла определяет имя готового конфига. Содержимое папки исключено из Git.

## Индивидуальная и массовая сборка

Запускайте команды из корня проекта. Для одного конфига укажите путь к файлу, для нескольких — путь к папке:

```sh
python3 converter.py --input vless-links/phone.txt
python3 converter.py --input vless-links/
```

В первом случае получится `json/phone.json`. Во втором конвертер создаст отдельный JSON для каждого файла верхнего уровня. Например, `phone.txt` и `tablet.txt` станут `phone.json` и `tablet.json`. Папка `json/` создаётся автоматически в текущем каталоге и исключена из Git. Скрытые файлы, вложенные папки и символические ссылки при сканировании папки пропускаются.

В каждом файле может быть одна или несколько VLESS-ссылок, по одной на строку. Все узлы одного файла попадают в один JSON. Выбирайте уникальные имена без учёта расширения. Если два файла дали бы одинаковое имя JSON, команда завершится до записи. Если отдельная ссылка невалидна, конвертер продолжит обработку остальных файлов и вернёт код ошибки. Существующий JSON для проблемного файла сохранится.

Флаг `--check` запускает предварительную проверку через sing-box:

```sh
python3 converter.py --input vless-links/ --check ./tests/sing-box
```

Команда выводит число успешно проверенных конфигов. В режиме `--check` выходные JSON-файлы не создаются и не заменяются. Если все конфиги прошли проверку, повторите команду без `--check`, чтобы их сохранить. То же поведение действует для режима с `-o`.

После генерации импортируйте нужные JSON-файлы в клиент sing-box. Проверка через ядро подтверждает загрузку конфига. Подключение и маршрутизация проверяются на целевом устройстве.

## Подписки 3x-ui

Создайте файл в [`subscriptions/`](subscriptions/) и запишите в него полный URL подписки одной строкой. Имя файла сохранится при загрузке списка ссылок.

```sh
python3 converter.py --subscription subscriptions/phone.txt
python3 converter.py --subscription subscriptions/
```

Первая команда создаёт `vless-links/phone.txt`. Вторая обрабатывает все видимые обычные файлы верхнего уровня в `subscriptions/`. Конвертер скачивает ответ, декодирует Base64 при необходимости и сохраняет все VLESS-ссылки, по одной на строку. Другие протоколы пропускаются. Успешная загрузка заменяет одноимённый файл целиком, в том числе созданный вручную. Если сервер недоступен, VLESS-ссылок нет или одна из них не поддерживается, предыдущий файл сохраняется, остальные подписки обрабатываются, а команда возвращает ошибку.

Чтобы затем сформировать отдельные JSON для всех списков, запустите:

```sh
python3 converter.py --input vless-links/
```

Флаг `--check ./tests/sing-box` также работает на этапе загрузки подписки. Он проверяет конфиг для полученного списка без записи выходных файлов. Для загрузки по умолчанию нужен HTTPS. Флаг `--allow-http` разрешает прямой HTTP-запрос. Перенаправления допускаются только на HTTPS.

## Одновременное обновление ссылок и JSON

Добавьте `-w` (`--write-json`) к `--subscription`, чтобы выполнить оба этапа одной командой:

```sh
python3 converter.py -s subscriptions/phone.txt -w
python3 converter.py -s subscriptions/ -w
python3 converter.py -s subscriptions/ -w -c ./tests/sing-box
```

Для `phone.txt` получатся `vless-links/phone.txt` и `json/phone.json`. Все подписки сначала скачиваются и конвертируются, затем скрипт заменяет файлы. Ошибка любой подписки отменяет обновление всего набора. Если ошибка случится во время записи, скрипт попытается восстановить уже заменённые файлы. `-c` проверяет все конфиги без записи результатов. `-w` используется с `-s` и без `-o`.

Параллельные запуски на запись из того же каталога блокируются через `.converter.lock`. После принудительного завершения процесса блокировка может остаться. Удаляйте её только после проверки, что конвертер больше не запущен. Автоматического восстановления после аварийного выключения во время записи нет.

Журнал `converter.log` в текущем каталоге общий для всех запусков. Он содержит время, идентификатор операции, этапы и результат. URL подписок, VLESS-ссылки, токены и ключи в журнал не записываются. Git игнорирует журнал.

## Сборка одного общего конфига

С `-o` конвертер пишет один JSON. Можно собрать его напрямую из файла подписки, папки подписок или нескольких локальных списков:

```sh
python3 converter.py --subscription subscriptions/phone.txt -o config.json
python3 converter.py --subscription subscriptions/ -o config.json
python3 converter.py --input vless-links/phone.txt --input vless-links/tablet.txt -o config.json
```

Для прямой передачи URL есть `-u` (`--url`). Чтобы токен не попадал в историю команд и список процессов, передавайте путь к файлу через `--subscription`. При сборке общего конфига `--input` также принимает сохранённое тело подписки в plain text или Base64.

## Параметры CLI

| Короткий ключ | Длинный ключ | Действие |
| --- | --- | --- |
| `-i PATH` | `--input PATH` | Конвертирует VLESS-ссылки из файла или всех файлов в папке в `json/<input_filename>.json`. Используйте `-o`, чтобы объединить входные файлы или stdin (`-`) в один JSON. |
| `-s PATH` | `--subscription PATH` | Загружает подписки из файла или всех файлов в папке и сохраняет VLESS-ссылки в `vless-links/<input_filename>`. Используйте `-o`, чтобы объединить подписки в один JSON. |
| `-o FILE` | `--output FILE` | Задаёт путь к одному общему JSON. |
| `-l URI […]` | `--vless URI […]` | Принимает одну или несколько VLESS-ссылок через пробел. Используйте с `-o`. |
| `-u URL […]` | `--url URL […]` | Принимает один или несколько URL подписок через пробел. Используйте с `-o`. |
| `-t FILE` | `--template FILE` | Выбирает JSONC-шаблон. |
| `-w` | `--write-json` | С `-s` сохраняет VLESS-списки и JSON за одну операцию. |
| `-c BIN` | `--check BIN` | Проверяет конфигурацию указанным sing-box без сохранения результата. |
| `-a` | `--allow-http` | Разрешает прямой HTTP-запрос к подписке. |
| `-h` | `--help` | Показывает справку. |

## Как работает конвертер

1. Читает VLESS URI или декодирует подписку из Base64. В смешанной подписке пропускает другие протоколы. Ошибка в VLESS-записи прерывает сборку.
2. Переносит параметры подключения в VLESS outbounds. Одинаковые подключения объединяются, совпадающие имена узлов получают числовые суффиксы.
3. Подставляет узлы в блок `outbounds` между комментариями `@ParserSTART` и `@ParserEND`. Метка `@VLESS@` и ссылки на старые VLESS-теги этого блока разворачиваются в список новых узлов. Если такой тег задан как `default` селектора, выбирается первый новый узел.
4. Записывает строгий JSON. Комментарии и завершающие запятые JSONC в результат не попадают.

В штатном [шаблоне](template.jsonc) группа `auto-proxy-out` проверяет новые узлы. Группа `proxy-out` по умолчанию использует автоматический выбор и позволяет выбрать узел вручную. `vpn ①` и `vpn ②` также получают список узлов. `ru VPN 🇷🇺` использует `direct-out`. Правила направляют домены из набора `ru-domains`, локальные адреса и другие заданные исключения через `direct-out`.

Свой JSONC-шаблон можно указать через `--template vless-links/custom-template.jsonc`. Маркеры должны охватывать целые элементы массива `outbounds`. Используйте стабильные теги групп в DNS и маршрутах, поскольку VLESS-узлы внутри блока заменяются. Массив `endpoints` сохраняется, включая любые записи между его маркерами `@ParserSTART_E` и `@ParserEND_E`.

## Поддержка VLESS

- Транспорты TCP (`tcp` и `raw`), WebSocket, gRPC в обычном режиме, HTTP/2 и HTTPUpgrade. Поддерживаются IPv4, IPv6 в квадратных скобках и доменные имена.
- Режимы `none`, TLS и REALITY. Для REALITY переносятся `sni`, `fp`, `pbk` и `sid`. При отсутствии `fp` используется `chrome`. `xtls-rprx-vision` поддерживается для TCP с TLS или REALITY.
- XHTTP, VLESS-шифрование, TCP с HTTP-заголовком, REALITY `pqv` и некоторые расширения TLS приводят к ошибке. Параметр Xray `spx` и неизвестные параметры URI пропускаются. Отключение проверки TLS через URI запрещено.

## Конфиденциальность

Готовый конфиг содержит UUID и параметры подключения. На macOS и Linux конвертер записывает его с правами `0600`. Git игнорирует `json/`, `config.json`, `config.local*.json`, файлы с префиксом `private-` и локальные файлы внутри `vless-links/` и `subscriptions/`. Для другого имени выходного файла проверьте правила Git перед коммитом.

При включённом Clash API и пустом секрете в шаблоне конвертер генерирует случайный секрет. Непустой секрет пользовательского шаблона сохраняется. Сообщения конвертера не выводят ссылки, токены и содержимое конфига.

## Тесты

В каталоге [`tests/`](tests/) находятся тесты и файл [`demo-vless.txt`](tests/demo-vless.txt) с демонстрационными ссылками для проверки генерации. Чтобы проверить свой демонстрационный набор, создайте `tests/private-demo.txt`, вставьте ссылки по одной на строку и подставьте этот путь в команду ниже. Git игнорирует файлы с префиксом `private-`.

Для проверки конфига ядром скачайте архив для своей платформы из [официального релиза sing-box 1.14.4](https://github.com/SagerNet/sing-box/releases/tag/v1.14.4) и положите извлечённый исполняемый файл в `tests/sing-box` (на Windows — `tests/sing-box.exe`). На macOS или Linux при необходимости выполните `chmod +x tests/sing-box`. Бинарник хранится локально и исключён из Git.

```sh
python3 -B -m unittest -v
python3 converter.py --input tests/demo-vless.txt --check ./tests/sing-box -o tests/demo-config.json
```

Тесты автоматически находят бинарник в `tests/`. Для другого расположения задайте `SING_BOX_TEST_BINARY`. Если бинарника нет, проверка через ядро пропускается, остальные тесты запускаются. Демонстрационный конфиг проверяет синтаксис и загрузку настроек без подключения к VPN.
